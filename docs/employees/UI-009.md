## Active Assignment — T-APP-CI-001: Fix `Frontend app tests (vitest)` CI failure

> Assigned by: CA (Chief Architect)
> Assigned on: 2026-08-15
> Status: 🟠 ACTIVE

### Background

CI run `31928841127` — the **Frontend app tests (vitest)** job fails (currently `allow_failure: true` / diagnostic in `.github/workflows/ci.yml`, matrix `module: app`, `path: src/app`). The CA reproduced the failure locally and traced the root cause.

### Root cause (determined by the CA — re-verify before acting)

`src/app/__tests__/ModuleIntegration.test.ts` imports `../../integration/ModuleIntegration.tsx` — a relative path that crosses **out of** `src/app/` **up into** the sibling `src/integration/` module. `ModuleIntegration.tsx` does `import React from 'react'`. The CI `app` job installs dependencies only in `src/app` (`working-directory: src/app` → `npm install`), so `node_modules` exists at `src/app/node_modules` only. Vite resolves bare imports by walking up the directory tree **from the importing file's location**; `ModuleIntegration.tsx` lives in `src/integration/`, so Vite searches `src/integration/node_modules` → `src/node_modules` → root `node_modules` — none of which are installed in this job. Result: `Failed to resolve import "react" from "../integration/ModuleIntegration.tsx"`.

This is **not** a missing declaration: both `src/app/package.json` and `src/integration/package.json` already declare `react`/`react-dom`. It is a **test-location / module-boundary / dependency-resolution** problem: a test in module A reaches into module B's source via a relative path, in a CI job that only installs module A's deps. This violates the **AD-010 module-local-config convention** (each module owns its own `package.json` + `vitest.config.ts` and is tested in isolation).

**Secondary bug in the same file:** `ModuleIntegration.test.ts` calls `vi.fn()` but imports only `{ describe, it, expect }` from `vitest` (missing `vi`). It works only because `globals: true` is set — fragile. Fix this while moving the file.

### Ownership note

UI-009 owns **both** `src/app/` and `src/integration/` (confirmed in this document, "Files" section). This fix is entirely within UI-009's ownership. No cross-employee module change is required or permitted.

### Implementation scope (files)

- `src/app/__tests__/ModuleIntegration.test.ts` — **delete** (remove the cross-boundary test).
- `src/integration/__tests__/ModuleIntegration.test.ts` — **create** (moved), importing `../ModuleIntegration.tsx` (local relative path, so `react` resolves from `src/integration/node_modules`).
- `src/integration/vitest.config.ts` — verify/adjust so `include` covers `**/__tests__/**/*.test.{ts,tsx}` and `environment: 'jsdom'` (the test imports React/JSX). Add `@vitejs/plugin-react` to the vitest plugins if `.tsx` JSX transform is required.
- `.github/workflows/ci.yml` — add a matrix entry `{ module: integration, path: src/integration, allow_failure: false }` to the `frontend-module-tests` job (consistent with AD-010 and the existing matrix; `src/integration` already has its own `package.json` + `vitest.config.ts`).
