## Active Assignment — T-CONV-CI-001: Fix `Frontend conversation tests (vitest)` CI failure

> Assigned by: CA (Chief Architect)
> Assigned on: 2026-08-15
> Status: ✅ COMPLETED

### Background

CI run `31928841127` — the **Frontend conversation tests (vitest)** job fails with `ERR_WORKER_OUT_OF_MEMORY` (`JS heap out of memory`), currently `allow_failure: true` / diagnostic in `.github/workflows/ci.yml` (matrix `module: conversation`, `path: src/conversation`). 5 of 6 test files pass (StreamManager 19, TypingIndicator 20, ChatInput 18, Chat 14, MarkdownRenderer 14 = 85 tests); the 6th file triggers a worker-level OOM. The CA reproduced the failure locally and traced the root cause.

### Root cause (determined by the CA — re-verify before acting)

**An infinite loop in `src/conversation/__tests__/useStreaming.test.ts`**, specifically the "starts streaming and updates message" test:

- The mock reader is `read: vi.fn().mockResolvedValue({ done: false, value: ... })` — it **always resolves with `done: false`**.
- `StreamManager.processStream` (in `src/conversation/streaming/StreamManager.ts`) runs a `while (true)` loop that `await`s `reader.read()`. Since `read()` never returns `done: true`, **the loop never terminates**.
- Each iteration pushes a chunk and calls `scheduleFlush()` → `window.setTimeout(flushBuffer, 0)`. Under `vi.useFakeTimers()` (set in `beforeEach`), the `setTimeout` callbacks do not auto-fire, but each `await reader.read()` resolves as a **microtask**, so the `while(true)` spins as an unbounded microtask loop — allocating buffer + closures + pending timers without end → **JS heap exhaustion → `ERR_WORKER_OUT_OF_MEMORY`**.
- The test's `waitFor(() => isStreaming === false)` can never succeed because the stream never completes.
- **Decisive proof (CA local run):** `npx vitest run __tests__/useStreaming.test.ts` OOMs **even when run completely alone** (0 tests complete, ~35s, then crash). This is **not** cross-file accumulation and **not** "StreamManager is broken" — `StreamManager.test.ts` alone passes in 11ms (19 tests). The OOM in the full run appears "after MarkdownRenderer" only because `useStreaming.test.ts` is the last file vitest attempts and crashes during its own execution.

**Secondary (non-fatal) contributor — real cleanup gap, fix it:** `StreamManager.test.ts` creates 19 `StreamManager` instances with **no `afterEach` destroy/cancel**, leaving pending `setTimeout(0)` flushes. This is not the OOM cause but must be fixed for hygiene.

### TypingIndicator `act()` warning — independent test-quality issue (fix it)

Not the cause of the OOM (different file, different mechanism; all 20 TypingIndicator tests pass), but must be fixed for test hygiene. `TypingIndicator.tsx` uses `setInterval` to update `activeDot` (React state). The test "updates active dot over time" calls `vi.advanceTimersByTime(400)`, which fires the interval callback → a `setActiveDot` state update **outside** `act(...)`. React emits the "not wrapped in act(...)" warning. Fix: wrap timer advances in `act(() => { vi.advanceTimersByTime(...); })`.
