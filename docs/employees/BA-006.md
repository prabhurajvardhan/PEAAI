## Summary

Integrated Amazon Bedrock as a new LLM provider in PEAAI's existing LLM abstraction with Amazon Nova Micro as the default model. The implementation follows the existing provider pattern (OpenAI, Anthropic, Ollama) and requires no changes to application code that uses the LLMClient interface.

**File**: `backend/.env.example`

## CA Repository Audit Notes (Context for BA-006)

The following observations were recorded by the CA during task assignment, from the actual repository at assignment time. BA-006 must re-verify against the current codebase (the source of truth) before acting on any of them; these are starting pointers, not conclusions.

- Frontend is a TypeScript monorepo under `src/`; app entry is `src/app/index.html` + `src/app/main.tsx` (React 18). There is currently NO root Vite build configuration; the root `package.json` build script is `tsc` and is V0.1-known-broken / diagnostic in CI (see `docs/engineering/CI.md`, AD-010). Vercel root/build/output configuration must account for the actual frontend build story — do not assume a working root Vite build exists.
- The only observed frontend API client is `src/components/auth/api.ts`, which already reads `VITE_API_URL` from the environment with a `/api/v1` relative fallback and contains no hardcoded localhost/production URLs. BA-006 should confirm no other HTTP callers hardcode URLs.
- No frontend WebSocket client implementation was found at assignment time (the backend exposes `/ws/` and `/ws/chat/{room_id}` under `backend/websocket/`). BA-006 should verify WS client status and document accordingly.
- Backend FastAPI app is `backend.api.main:app`; config is `backend/api/config.py` (pydantic-settings, reads `.env`). The backend already exposes `/` and `/health` health endpoints that do not surface secrets — re-verify before adding any new health endpoint (Task 13).
- CORS already uses `settings.ALLOWED_ORIGINS` (default `["*"]`) with `allow_credentials=True`. This is env-driven; confirm staging tightening.
- `DATABASE_URL` (PostgreSQL, default `postgresql://postgres:postgres@localhost:5432/peaai`) is consumed in `backend/database/__init__.py` and `backend/migrations/env.py`. Alembic config is `backend/alembic.ini`; migrations live in `backend/migrations/versions/`.
- `REDIS_URL` (default `redis://localhost:6379/0`) is used by `RedisSessionStore`; `SessionManager` falls back to `InMemorySessionStore`. Verify the staging backend selects the Redis-backed store.
- Storage (`backend/storage/manager.py`, `backend/storage/cdn.py`) writes to the local filesystem at `STORAGE_PATH` (default `./storage`) and is configurable via `CDN_BASE_URL`. Local-FS persistence is likely unsafe on Render's ephemeral disk — document this limitation (Task 12) without redesigning the storage architecture.
- `backend/ai/llm/config.py` reads `LLM_API_KEY`, `OLLAMA_BASE_URL`, and `OPENAI_ORGANIZATION` from the environment; default provider is OpenAI.
- Insecure development defaults (e.g. `SECRET_KEY = "your-secret-key-change-in-production"`, localhost DB/Redis URLs) MUST be overridden via environment variables in staging and never committed (Task 9). No `.env` files are tracked; `.gitignore` covers `.env` / `.env.local`.
- CI gating signal is the backend pytest job (`python -m pytest backend/`) plus the jest/vitest frontend legs described in `docs/engineering/CI.md`. BA-006 must keep these green.
